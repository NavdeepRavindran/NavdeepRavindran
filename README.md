### Repository structure

```
NavdeepRavindran/                  ← repo name must match your username exactly
├── README.md
└── .github/
    └── workflows/
        ├── snake.yml              ← contribution snake
        ├── pacman.yml             ← Pac-Man contribution graph
        └── metrics.yml            ← optional full metrics dashboard
```

### 1. Create the special repo
Create a public GitHub repo named **exactly** `NavdeepRavindran` (same as your username). GitHub automatically shows its `README.md` on your profile page.

### 2. Enable write permissions
**Settings → Actions → General → Workflow permissions → Read and write permissions → Save.**
Both `snake.yml` and `pacman.yml` need this to push their generated SVGs to the `output` branch.

### 3. Add the workflow files
Copy `snake.yml` and `pacman.yml` (and, optionally, `metrics.yml`) into `.github/workflows/` in your repo.

### 4. Run each workflow once manually
**Actions tab → select the workflow → Run workflow.** This creates the `output` branch and generates the first SVGs — after that, each workflow keeps itself updated on its own schedule.

### 5. About the GitHub Stats fix
The default `github-readme-stats.vercel.app` demo instance is shared by everyone using the project and regularly hits GitHub's API rate limit, which is what was breaking your stats and top-languages cards. This README points them at `github-readme-stats-sigma-five.vercel.app`, a community-hosted alternate instance that avoids the same bottleneck. It's still a third-party deployment (not officially run by the project), so if it ever goes down, the most reliable long-term fix is deploying your own free instance on Vercel from the [github-readme-stats repo](https://github.com/anuraghazra/github-readme-stats) and swapping the domain in the two image URLs.

### 6. 3D Contribution Calendar — intentionally removed
Per your request, the 3D contribution widget has been left out entirely so there's nothing broken on the page. If you want it back later, it's a one-file addition (`profile-3d.yml` using `yoshi389111/github-profile-3d-contrib`) — just ask.

### 7. Metrics dashboard (optional)
`metrics.yml` needs a **Personal Access Token** (not the default `GITHUB_TOKEN`) with `read:user` scope, saved as a repo secret named `METRICS_TOKEN`, because it reads data the default token can't access. Skip this workflow entirely if you don't want the extra dashboard — nothing else in the README depends on it.
